## Задача

Дано n-арное дерево (у узла может быть сколько угодно детей). Собрать значения всех узлов в плоский массив в порядке обхода: узел, затем его поддеревья слева направо (pre-order).

## Почему именно рекурсия

Дерево рекурсивно по определению: узел — это значение плюс список детей, каждый из которых сам узел. Обход записывается дословно:

```js
function walk(node) {
  result.push(node.value);          // 1. обработать себя
  for (const child of node.children ?? []) {
    walk(child);                     // 2. рекурсивно — каждого ребёнка
  }
}
```

Пять строк, и это вся задача. Итеративная версия (с явным стеком) длиннее и менее очевидна — хотя формально эквивалентна.

## Как это выглядит по шагам

<Viz algo="flatten-tree" />

Стек вызовов в визуализации растёт на каждом спуске в ребёнка и схлопывается на возврате. Глубина стека в любой момент равна глубине текущего узла.

## Сложность

**Время — O(n).** Каждый узел посещается ровно один раз.

**Память — O(h)** на стек вызовов, где h — высота дерева. Для сбалансированного дерева h = log n; для вырожденного (список) h = n.

## Базовый случай

```js
for (const child of node.children ?? []) walk(child);
```

Здесь он **неявный**: у листа нет детей, цикл не выполняется, рекурсия возвращается. Это чище, чем `if (!node) return`, потому что `null`-узлов нет в структуре.

Но если дерево представлено с возможными `null` (часто в LeetCode), проверка нужна — иначе обращение `node.value` упадёт.

## Ловушки

- **Порядок обхода.** «Себя, потом детей» — pre-order. Если нужны «детей, потом себя» (post-order) — поменять местами две строки. Путаница в порядке — частый баг.
- **Глубокое вырожденное дерево.** Список из 10 000 узлов, представленный как дерево, где каждый имеет одного ребёнка, даст рекурсию глубины 10 000 и `RangeError`. Тогда — итеративный стек.
- **Мутация результата снаружи.** `result` объявлен снаружи `walk` — это нормально для учебного кода, но в чистой функции лучше накапливать через возврат: `return [node.value, ...children.flatMap(walk)]`. Чище, но аллоцирует массивы на каждом шаге.

## От итеративного стека ничем не отличается

Любая рекурсия = неявный стек вызовов. Заменив его явным массивом-стеком, получим ту же логику без риска переполнения:

```js
const stack = [root];
while (stack.length) {
  const node = stack.pop();
  result.push(node.value);
  // детей кладём в обратном порядке, чтобы обрабатывались слева направо
  for (const child of [...(node.children ?? [])].reverse()) stack.push(child);
}
```

Это ровно [стек из темы 08](/t/stack), применённый к дереву. Та же связь: DFS по дереву = стек, BFS по дереву = очередь.

Рекурсия — это не алгоритм, а **способ рассуждения**. Функция вызывает сама себя для меньшей версии задачи. Звучит как игра в поддавки, пока не сталкиваешься с двумя реальностями: стек вызовов ограничен, а наивная рекурсия экспоненциальна.

Тема отвечает на два вопроса: когда рекурсия уместна, и как убить экспоненту, не убив при этом читаемость.

## Когда рекурсия естественна

Структура данных рекурсивна по определению — рекурсия под неё заточена:

- **Деревья.** Узел содержит детей, каждый ребёнок — узел. Обход — «обработай себя, потом детей».
- **Графы.** DFS — «пометь себя посещённым, рекурсивно зайди в соседей».
- **«Разделяй и властвуй».** Merge sort, quicksort: реши для половинок, склей.
- **Вложенные структуры.** Парсинг скобок, раскодирование `3[a2[c]]`.

Если данные имеют произвольную глубину — рекурсия или явный стек. Линейные структуры (массивы, строки) чаще решаются итеративно.

## Стек вызовов — это не бесплатно

Каждый рекурсивный вызов кладёт кадр на стек: аргументы, локальные переменные, адрес возврата. Глубина рекурсии = память O(глубина). Для дерева высоты h это O(h); для вырожденного дерева (по сути списка) — O(n).

```js
const sum = (n) => (n === 0 ? 0 : n + sum(n - 1));
sum(100000);  // RangeError: Maximum call stack size exceeded
```

V8 ограничивает стек примерно 10 000 кадрами. На больших входах линейная рекурсия падает. Решение — **хвостовая рекурсия** (которую V8, кстати, поддерживает не во всех случаях) или явный итеративный цикл.

## Экспоненциальный взрыв

Наивный Фибоначчи:

```js
const fib = (n) => (n <= 1 ? n : fib(n - 1) + fib(n - 2));
```

`fib(40)` делает ~миллиард вызовов. Дерево вызовов перекрывается: `fib(3)` считается множество раз. Каждое перекрытие — лишняя работа.

Решение — **мемоизация**: запоминаем результаты. `fib(k)` считается ровно один раз, дерево из экспоненциального становится линейным. Тот же приём превращает наивное «перебор с рекурсией» в динамическое программирование.

## Базовый случай

Без него рекурсия бесконечна и падает на переполнении стека. Базовый случай — это **простейшая версия задачи, ответ на которую известен без рекурсии**:

- Дерево: «узел без детей» или «null».
- Фибоначчи: `n <= 1`.
- Сортировка: «массив из одного элемента уже отсортирован».

Проверка базового случая обязана быть **первой** строкой функции. Если запустить рекурсию до проверки — можно уйти в бесконечность даже на тривиальном входе.

## Рекурсия против итерации

Любую рекурсию можно переписать в итерацию с явным стеком. Вопрос — что читаемее:

- Обход дерева — рекурсия в разы читаемее.
- Линейный проход — итерация проще, и не рискует переполнением стека.

Правило: **рекурсия для структур с ветвлением, итерация для линейного потока.** Если глубина ограничена логарифмом (сбалансированное дерево, «разделяй и властвуй») — рекурсия безопасна. Если глубина линейна — лучше цикл.

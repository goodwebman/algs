## Задача

Посчитать n-е число Фибоначчи: `0, 1, 1, 2, 3, 5, 8, 13, …`, где каждое равно сумме двух предыдущих.

## Наивное решение

```js
const fib = (n) => (n <= 1 ? n : fib(n - 1) + fib(n - 2));
```

Это **буквально** математическое определение, и оно работает. Для `fib(6)`. Для `fib(20)`. И намертво виснет на `fib(40)`.

## Почему экспоненциально

`fib(5)` вызывает `fib(4)` и `fib(3)`. `fib(4)` тоже вызывает `fib(3)` — и тот же `fib(3)` считается заново, полностью. Дерево вызовов перекрывается: одни и те же подзадачи перевычисляются многократно.

Посчитай узлы на визуализации `fib(6)`: их около двух десятков, хотя различных подзадач всего семь. Для `fib(n)` узлов порядка 2ⁿ, а уникальных — n. Разрыв — это и есть лишняя работа.

## Мемоизация

Запоминаем уже посчитанные значения:

```js
const memo = new Map();
const fib = (n) => {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);   // уже считали — берём готовое
  const result = fib(n - 1) + fib(n - 2);
  memo.set(n, result);
  return result;
};
```

Теперь `fib(k)` считается **ровно один раз**. Дерево из экспоненциального превращается в линейное. `fib(40)` — мгновенно, `fib(100)` — мгновенно.

## Это и есть динамическое программирование

«Сверху вниз с мемоизацией» — одна из двух форм DP. Мы не изменили структуру рассуждения (всё та же рекурсия), просто перестали перевычислять. То же самое «снизу вверх» — итеративно:

```js
const fib = (n) => {
  if (n <= 1) return n;
  let a = 0, b = 1;
  for (let i = 2; i <= n; i += 1) [a, b] = [b, a + b];
  return b;
};
```

Та же сложность O(n), но O(1) памяти (хранятся только два последних) и никакого стека. Для Фибоначчи итеративная версия лучше во всём — кроме как иллюстрации идеи мемоизации.

## Сложность

| Подход | Время | Память |
|---|---|---|
| Наивная рекурсия | O(2ⁿ) | O(n) стек |
| Мемоизация | O(n) | O(n) |
| Итеративный | O(n) | O(1) |

## Ловушки

- **Память мемо-кэша растёт.** Для длинных последовательностей он не очищается. В замкнутой функции это нормально; в долгоживущем сервисе — утечка.
- **`Map` против объекта.** Для числовых ключей `Map` надёжнее: объект приведёт ключи к строкам, и `1` с `'1'` схлопнутся.
- **BigInt для больших n.** `fib(79)` уже не помещается в `Number.MAX_SAFE_INTEGER`. Точность теряется тихо — нужен `BigInt`.

## Когда применять

Мемоизация — не «оптимизация ради оптимизации». Она работает, когда рекурсия **перевычисляет одни и те же подзадачи**. Если подзадачи все разные (например, обход дерева, где каждый узел посещается один раз) — мемоизация ничего не даст.

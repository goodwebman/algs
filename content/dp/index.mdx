Динамическое программирование пугает названием, но идея простая: **перебор без повторов**. Если наивная рекурсия решает одну и ту же подзадачу многократно — запомни ответ и не считай заново.

Ты это уже видел: [мемоизация Фибоначчи](/t/recursion/fibonacci) — это DP.

## Когда DP применимо

Два признака, оба обязательны:

**1. Оптимальная подструктура.** Оптимум задачи собирается из оптимумов подзадач. «Минимум монет для 30» строится из «минимума монет для 20» плюс десятка.

**2. Перекрывающиеся подзадачи.** Одни и те же подзадачи встречаются многократно. Если все подзадачи разные — DP не нужно, это просто рекурсия.

## Рецепт из трёх пунктов

Весь DP сводится к тому, чтобы найти:

1. **Состояние** — что описывает подзадачу. `dp[s]` = минимум монет для суммы `s`.
2. **Переход** — как из решённых подзадач получить текущую. `dp[s] = 1 + min(dp[s - coin])`.
3. **База** — тривиальный случай. `dp[0] = 0`.

Найдёшь эти три вещи — код пишется механически. Не найдёшь — никакие приёмы не помогут. **Вся сложность DP в формулировке состояния**, а не в кодировании.

## Две формы

**Сверху вниз (мемоизация).** Рекурсия + кэш. Ближе к тому, как думаешь, вычисляет только нужные подзадачи. Платит стеком вызовов.

**Снизу вверх (таблица).** Итеративное заполнение массива от базы. Без рекурсии, часто меньше памяти, но считает все подзадачи — даже ненужные.

Начинай с мемоизации — её проще вывести из наивной рекурсии. Переписывай в таблицу, если нужен контроль над памятью.

## Оптимизация памяти

Если переход смотрит только на несколько предыдущих состояний, всю таблицу хранить не нужно:

```js
// Фибоначчи: dp[i] зависит от dp[i-1] и dp[i-2]
let a = 0, b = 1;   // вместо массива на n элементов
```

То же для DP по сетке, где строка зависит только от предыдущей: O(n) вместо O(n²).

## Классические задачи

- **Размен монет** — минимум монет для суммы.
- **Рюкзак** — максимум ценности при ограничении веса.
- **Наибольшая общая подпоследовательность** — DP по двум измерениям.
- **Пути в сетке** — сколько маршрутов из угла в угол.
- **Наибольшая возрастающая подпоследовательность** — O(n²) через DP или O(n log n) через бинпоиск.

## DP против жадности

[Жадность](/t/greedy) быстрее, но требует доказательства. DP медленнее, но даёт гарантированный оптимум **всегда**.

Ровно эта пара видна на размене монет: жадность на `[25,10,1]` даёт 6 монет вместо 3, DP — правильные 3.

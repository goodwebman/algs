## Задача

Минимальное число монет, чтобы набрать сумму. Если набрать нельзя — `−1`.

Это [та самая задача](/t/greedy/coin-change-greedy), на которой жадность врёт. DP даёт гарантированный оптимум на любом наборе.

## Рецепт: состояние, переход, база

**Состояние:** `dp[s]` — минимальное число монет для суммы `s`.

**Переход:** чтобы набрать `s`, возьмём какую-то монету `coin` и добавим её к решению для `s - coin`:

```
dp[s] = 1 + min(dp[s - coin])   по всем монетам, что помещаются
```

**База:** `dp[0] = 0` — нулевую сумму набирают нулём монет.

Всё. Дальше код пишется механически:

```js
const dp = new Array(amount + 1).fill(Infinity);
dp[0] = 0;

for (let sum = 1; sum <= amount; sum += 1) {
  for (const coin of coins) {
    if (coin > sum) continue;
    if (dp[sum - coin] === Infinity) continue;   // подзадача нерешаема
    dp[sum] = Math.min(dp[sum], dp[sum - coin] + 1);
  }
}
```

## Почему это работает, а жадность нет

Жадность **фиксирует** первый выбор и идёт дальше. DP **пробует все** варианты первой монеты и берёт лучший — но каждую подзадачу решает один раз, поэтому не превращается в экспоненциальный перебор.

На `[25,10,1]` и сумме 30 DP рассмотрит и вариант «начать с 25», и вариант «начать с 10», и выберет второй.

Таблица заполняется слева направо. Каждая ячейка `dp[s]` смотрит на уже заполненную `dp[s - coin]` — это и есть «использовать решённую подзадачу».

## Порядок циклов

Внешний цикл по суммам, внутренний по монетам. Так к моменту вычисления `dp[s]` все меньшие суммы уже готовы.

Поменять циклы местами здесь можно (ответ не изменится), но в задаче «сколькими способами набрать сумму» порядок **критичен**: он определяет, считаются ли `1+2` и `2+1` разными способами. Это классическая ловушка на собеседовании.

## Сложность

**Время — O(amount × количество монет).** Обрати внимание: это **псевдополиномиальная** сложность — она зависит от **значения** amount, а не от размера его записи. Для amount = 10⁹ таблица не влезет в память, хотя число «amount» занимает 4 байта.

**Память — O(amount)** на таблицу.

## Ловушки

- **`Infinity` как «нерешаемо».** Без проверки `dp[s - coin] === Infinity` получится `Infinity + 1`, что всё ещё `Infinity` — здесь безопасно, но в задачах с целочисленным максимумом даст переполнение.
- **Возврат `Infinity` вместо `−1`.** Условие обычно требует `−1`. Преобразовать в конце.
- **Пустой набор монет.** `dp` останется в `Infinity` для всех сумм кроме нуля — корректно, но проверь.
- **Восстановление самих монет.** Таблица даёт количество, но не состав. Для состава нужно хранить, какая монета дала минимум, и пройти назад.

## Восстановление ответа

```js
const from = new Array(amount + 1).fill(-1);
// в момент обновления: from[sum] = coin;

// потом идём назад:
let s = amount;
while (s > 0) { result.push(from[s]); s -= from[s]; }
```

Приём общий для всего DP: таблица даёт **значение** оптимума, отдельный массив «откуда пришли» даёт **само решение**.

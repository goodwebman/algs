## Задача

Разменять сумму минимальным числом монет заданных номиналов.

## Жадное решение

Берём самую крупную монету, которая помещается, повторяем:

```js
const sorted = [...coins].sort((a, b) => b - a);
for (const coin of sorted) {
  while (left >= coin) {
    left -= coin;
    taken.push(coin);
  }
}
```

Просто, быстро, и на привычных нам монетах **работает**: рубли, доллары, евро — все канонические наборы.

## Где оно ломается

`[25, 10, 1]`, сумма 30:

| | Монеты | Всего |
|---|---|---|
| Жадно | 25 + 1+1+1+1+1 | **6** |
| Оптимально | 10 + 10 + 10 | **3** |

Взяв 25, алгоритм загнал себя в остаток 5, где нет ничего кроме единиц. Он не может «передумать» — в этом и суть жадности.

Переключи пресеты: первый — канонический набор, там жадность оптимальна. Второй — контрпример.

## Почему это важнее, чем кажется

Жадный алгоритм **не сообщает об ошибке**. Он всегда возвращает какой-то ответ, и этот ответ выглядит правдоподобно. На тестах с обычными монетами всё сходится. Проблема всплывает на нестандартном наборе — например, если номиналы приходят из конфига.

Это худший вид бага: молчаливый, зависящий от данных, невоспроизводимый на типовых тестах.

## Как проверить свой набор

Набор канонический, если для **всех** сумм от 1 до некоторого предела жадный ответ совпадает с оптимальным. Проверяется прямым сравнением с DP:

```js
for (let sum = 1; sum <= maxTest; sum += 1) {
  if (greedy(coins, sum).length !== dp(coins, sum)) {
    // не канонический — жадность нельзя
  }
}
```

Известен результат: достаточно проверить суммы до примерно `самый крупный + второй по величине`. Если на этом отрезке расхождений нет — набор канонический.

## Второй недостаток: тупик

`[7, 5]`, сумма 11. Жадность берёт 7, остаётся 4 — разменять нечем, алгоритм сдаётся. При этом верный ответ здесь тоже отсутствует (11 не разложить), но жадность не отличает «нельзя» от «я зашла не туда».

На наборе `[7, 5]` и сумме 10 жадность взяла бы 7, застряла бы на остатке 3 — и не нашла бы ответ `5 + 5`, который существует.

## Сложность

**Время — O(n log n)** на сортировку плюс O(количества монет в ответе) на сам размен.

**Память — O(1)** сверх результата.

Жадность быстрее DP (`O(amount · n)`) — за это её и любят. Но только там, где она корректна.

## Вывод

Жадность — не «упрощённое DP». Это другой алгоритм с другими гарантиями. Применяй, когда доказал корректность или проверил набор. Не уверен — [бери DP](/t/dp/coin-change-dp).

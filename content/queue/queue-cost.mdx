## Проблема

```js
const queue = [];
queue.push(item);          // O(1)
const next = queue.shift();  // ❌ O(n)
```

Название `shift` подсказывает, что происходит на самом деле: массив **сдвигается**. Удалить первый элемент, не тронув остальные, в плотном массиве нельзя — все индексы должны уменьшиться на единицу, а значит вся лента физически переписывается.

## Насколько это дорого

<Viz algo="queue-cost" />

Счётчики под визуализацией показывают разницу: на очереди из n элементов `shift()` суммарно копирует `n + (n-1) + … + 1 ≈ n²/2` элементов. Head-указатель — ноль.

Для BFS это означает: обход графа на 10 000 вершин делает около 50 миллионов лишних копирований. На 100 000 — вкладка зависает на секунды. И самое неприятное: **алгоритм при этом корректен**, просто необъяснимо медленный.

## Решение: голова — это указатель

```js
const items = [];
let head = 0;

const enqueue = (x) => items.push(x);       // O(1)
const dequeue = () => items[head++];        // O(1)
const isEmpty = () => head >= items.length;
```

Ничего не двигается. «Удалённые» элементы остаются в массиве слева от `head` — они просто никого не интересуют.

## А как же память

Кажется, что мусор слева от `head` — утечка. На практике нет:

- Массив всё равно вырастает до размера, равного числу **всех** добавленных элементов — при `shift()` он был бы такого же максимального размера в пике.
- Для BFS это O(V), то есть ровно та память, которую алгоритм и так тратит на `visited`.

Если очередь долгоживущая и через неё проходят миллионы элементов, добавляют периодическое усечение:

```js
if (head > 1000 && head * 2 > items.length) {
  items.splice(0, head);   // один O(n) вместо тысячи
  head = 0;
}
```

Одна дорогая операция раз в тысячу дешёвых — амортизированно всё ещё O(1).

## Когда `shift()` допустим

Когда элементов десятки. На маленькой очереди разница неизмерима, а `shift()` читается привычнее. Правило: **как только очередь растёт с размером входа — head-указатель**.

## Настоящий дек

Если нужны O(1) на **обоих** концах (`unshift`/`shift` и `push`/`pop`) — нужен кольцевой буфер: массив фиксированного размера с двумя указателями по модулю длины. Для 99% задач это избыточно.

## Похожие ловушки

- `splice(0, 1)` — то же самое, что `shift`.
- `unshift` в цикле — [квадратичное заполнение массива](/t/two-pointers/sorted-squares).
- `concat` в цикле вместо `push` — новый массив на каждой итерации.

## Задача

В сетке `0` — пусто, `1` — свежий апельсин, `2` — гнилой. Каждую минуту гнилой заражает свежих соседей (вверх/вниз/влево/вправо). За сколько минут сгниют все? Если какой-то свежий недостижим — вернуть `−1`.

## Инсайт: многоисточниковый BFS

Обычный BFS имеет один старт. Здесь источников несколько — все гнилые апельсины стартуют одновременно. Приём: **кладём все источники в очередь сразу** и обходим по уровням.

Каждый «уровень» очереди — это одна минута заражения. Обрабатываем не по одному элементу, а **волнами фиксированного размера»: фиксируем длину очереди в начале минуты и обрабатываем ровно столько элементов.

```js
while (head < queue.length) {
  const waveSize = queue.length - head;
  for (let i = 0; i < waveSize; i += 1) {
    // обработать один гнилой, заразить свежих соседей
  }
  if (head < queue.length) minutes += 1; // была работа — прошла минута
}
```

## Почему проверка «остался ли свежий» обязательна

Волна останавливается, когда очередь пуста. Но «очередь пуста» ≠ «все заражены»: свежий апельсин, окружённый нулями, никогда не попадёт в очередь. Поэтому в конце нужно пересчитать свежие — если остались, ответ `−1`.

## Сложность

**Время — O(rows · cols).** Каждая ячейка попадает в очередь максимум один раз.

**Память — O(rows · cols)** на очередь в худшем случае (всё гнилое с самого начала).

## Ловушки

- **Минуту увеличивать только если была работа.** Если за волну ничего не заразили, лишняя минута не нужна. Проверка `head < queue.length` после внутреннего цикла.
- **Заражение в момент добавления, а не обработки.** Свежий, добавленный в очередь, должен сразу стать гнилым в сетке — иначе его добавит сосед.
- **Нет свежих вовсе.** Если `fresh === 0` с самого старта, ответ 0, а не −1: заражать некого, но и ждать нечего.

## Обобщение

«Многоисточниковый BFS» — общий приём. Любая задача вида «от нескольких очагов что-то расползается с одинаковой скоростью» решается им: расстояние от ближайшего источника, время пожара, минимальное расстояние до стены.

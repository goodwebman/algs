Очередь — это FIFO: первый пришёл, первый ушёл. Очередь в магазине, конвейер, буфер событий.

Механика зеркальна стеку, и именно поэтому их путают. Тест тот же, что у стека, с обратным ответом: **«какой элемент я обрабатываю следующим — самый старый или самый новый?».** Старый → очередь. Новый → стек.

## Маркеры задачи на очередь

- **«По уровням» / «волна за волной».** BFS расширяется слоями: сначала соседи на расстоянии 1, потом 2. Это определение очереди.
- **«Кратчайший путь без весов».** В невзвешенном графе BFS гарантированно даёт кратчайший.
- **«Сначала пришёл — первым обработан».** Буферизация, планировщик задач, сглаживание потока.

## Главная ловушка темы: `shift()`

```js
const queue = [];
queue.push(item);        // O(1) — enqueue
const next = queue.shift();   // ❌ O(n), не O(1)!
```

`shift()` не «удаляет первый элемент» — он **сдвигает весь хвост на одну позицию влево**, чтобы заполнить дыру. Это O(n). В цикле по n элементам это превращает линейный алгоритм в квадратичный.

BFS на 10 000 вершинах с `shift()` делает около 50 миллионов лишних копирований. На 100 000 — зависает на секунды. Это самая частая скрытая O(n²) в граph-задачах.

## Правильная очередь

Голова — это указатель, а не физический первый элемент:

```js
const items = [];
let head = 0;

const enqueue = (x) => items.push(x);     // O(1)
const dequeue = () => items[head++];      // O(1) — ничего не двигается
const isEmpty = () => head >= items.length;
```

«Удалённые» элементы остаются в массиве, просто `head` их обходит. Памяти это не ест — массив того же размера. Счётчик `reads` под визуализацией выше показывает разницу буквально.

Если нужен полноценный дек (двусторонняя очередь с O(1) на обоих концах) — берётся кольцевой буфер. Но для 99% задач хватает head-указателя.

## Что в теме

1. **shift() против head-указателя** — почему одна функция превращает BFS в O(n²).
2. **Кратчайший путь через BFS** — основное применение: волна, visited, parent-карта.
3. **Гниющие апельсины** — многоисточниковый BFS по уровням на сетке.

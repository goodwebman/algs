## Задача

Найти **все уникальные** тройки чисел, дающие в сумме ноль. Одна и та же тройка не должна попасть в ответ дважды — даже если её можно собрать из разных позиций массива.

Вход `[-1, 0, 1, 2, -1, -4]` даёт ровно два ответа: `[-1, -1, 2]` и `[-1, 0, 1]`.

## Инсайт: зафиксировать один и свести к паре

Перебор всех троек — O(n³). Но если **зафиксировать** первый элемент `nums[i]`, задача превращается в знакомую: найти в хвосте массива пару с суммой `−nums[i]`. А это уже [два указателя за O(n)](/t/two-pointers/two-sum-sorted).

Итого: внешний цикл O(n) × два указателя O(n) = **O(n²)**. На порядок лучше перебора.

Цена входа — сортировка. Без неё два указателя не работают, а заодно сортировка даёт второй бонус: одинаковые значения становятся соседями, и дубликаты можно пропускать простым сравнением с соседом.

## Уникальность — вот где вся сложность

Именно на дубликатах эту задачу и заваливают. Пропуск нужен в **трёх** местах, и каждый отвечает за свой случай:

```js
// 1. Первый элемент: все тройки с этим значением уже собраны
if (i > 0 && nums[i] === nums[i - 1]) continue;

// после того как тройка найдена:
// 2. и 3. Пропускаем повторы обоих найденных значений
while (left < right && nums[left] === nums[left + 1]) left += 1;
while (left < right && nums[right] === nums[right - 1]) right -= 1;
```

Забыть первый — и на входе `[-1,0,1,2,-1,-4]` тройка `[-1,0,1]` вернётся дважды. Забыть второй и третий — и на `[0,0,0,0]` вернётся четыре одинаковые тройки вместо одной.

<Note tone="trap" title="Почему нельзя просто отфильтровать в конце">
  Можно — через `Set` по строковому ключу. Но это лишний проход, лишняя память и потеря контроля:
  на входе из 3000 нулей алгоритм без пропусков сначала соберёт миллионы одинаковых троек и только
  потом их схлопнет. Пропуск на месте не даёт им появиться вообще.
</Note>

## Ранний выход

```js
if (nums[i] > 0) break;
```

Массив отсортирован. Если самый левый (то есть минимальный) элемент тройки уже положителен, то и два остальных положительны — сумма нулём быть не может. Дальше смотреть незачем.

Это не меняет O-оценку, но на реальных данных срезает половину работы.

## Сложность

**Время — O(n²).** Сортировка O(n log n) поглощается внешним циклом O(n), внутри которого линейный проход двумя указателями.

**Память — O(n)** на копию массива для сортировки. Если разрешено портить вход, можно сортировать на месте и получить O(log n) (стек рекурсии сортировки). Здесь вход не мутируется намеренно: функция, молча переставляющая элементы в переданном массиве, — источник неприятных багов у вызывающего.

## Ловушки

- **Сортировка без компаратора.** `[10, 9, 1].sort()` даёт `[1, 10, 9]` — `sort` по умолчанию сравнивает **строки**. Для чисел компаратор `(a, b) => a - b` обязателен всегда.
- **Мутация входа.** `nums.sort()` сортирует исходный массив. `[...nums].sort()` — копию.
- **`i < nums.length - 2`.** Тройке нужно три элемента; идти до конца бессмысленно и на массиве из двух элементов даст лишние итерации.

## Задача

Проверить, читается ли строка одинаково слева направо и справа налево. Регистр не важен, всё, что не буква и не цифра, игнорируется.

`"A man, a plan, a canal: Panama"` — палиндром. `"race a car"` — нет.

## Наивное решение

```js
const isPalindrome = (s) => {
  const clean = s.toLowerCase().replace(/[^a-z0-9]/g, '');
  return clean === [...clean].reverse().join('');
};
```

Работает, читается, и в проде я бы такое принял. Но здесь есть что улучшить: `replace` создаёт одну новую строку, `reverse().join('')` — ещё одну плюс массив. Это O(n) дополнительной памяти там, где хватило бы O(1).

<Note tone="trap" title="И одна настоящая ошибка">
  Регулярка `[^a-z0-9]` выкидывает всё, кроме латиницы. На кириллице она сотрёт строку целиком, а
  `[^a-zа-я0-9]` — почти целиком: буква «ё» **не входит** в диапазон `а-я` в Unicode (она стоит после
  «я», в позиции U+0451). Правильно — `\p{L}` с флагом `u`.
</Note>

## Инсайт: пропускать мусор на лету

Указатели идут навстречу. Если под указателем не буква и не цифра — двигаем этот указатель и **не двигаем второй**, повторяя проверку. Никакой очистки строки не нужно: мусор просто проскакивается по ходу.

Условие `left < right` внутри пропусков обязательно. Строка `".,!"` состоит из одних знаков: без проверки указатель уедет за границу массива и `chars[left]` вернёт `undefined`.

## Сложность

**Время — O(n).** Каждый указатель проходит свою половину строки, суммарно каждый символ смотрится один раз.

**Память — O(1)** для ASCII. Формально `[...input]` создаёт массив — это O(n), но он нужен только для корректной работы с юникодом (см. ниже); на чистом ASCII можно работать прямо по индексам строки.

## JS-специфика: строка — это не массив символов

`"👍".length === 2`. Строки в JS — это последовательности UTF-16 code units, а не символов. Эмодзи, редкие иероглифы и некоторые математические символы занимают по две ячейки (суррогатная пара), и обращение `s[i]` вернёт половину символа.

```js
const s = '👍a👍';
s.length;        // 5, а не 3
s[0];            // '\uD83D' — половинка эмодзи
[...s].length;   // 3 — спред идёт по code points
```

Поэтому в разборе стоит `const chars = [...input]`: спред-оператор и `for…of` обходят строку по code points, а индексирование — нет. Для задач с эмодзи это разница между работающим кодом и мусором.

Отдельно: `\p{L}` (любая буква) и `\p{N}` (любая цифра) требуют флага `u` — без него движок не поймёт синтаксис Unicode property escapes и бросит `SyntaxError`.

## Ловушки

- Строка из одних знаков препинания и пустая строка — палиндромы. Многие решения на них падают.
- `toLowerCase()` на каждой итерации создаёт новую строку. Для двух символов это копейки, но в горячем цикле над длинными строками — заметно.
- Турецкая «I»: `'I'.toLowerCase()` даёт `'i'`, но в турецкой локали правильный ответ — `'ı'`. Если задача про локали, нужен `toLocaleLowerCase`.

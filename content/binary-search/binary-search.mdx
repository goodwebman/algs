## Задача

Найти индекс элемента в **отсортированном** массиве. Если элемента нет — вернуть `−1`.

## Инсайт: инвариант отрезка

**Если ответ существует, он лежит внутри отрезка `[left, right]`.**

На каждом шаге смотрим на середину. Если она меньше цели — вся левая половина (включая середину) гарантированно меньше цели, ответа там нет, отбрасываем. Если середина больше — отбрасываем правую. Если равна — нашли.

За шаг отрезок уменьшается вдвое. Чтобы из миллиона дойти до одного, нужно `log₂(10⁶) ≈ 20` делений. Отсюда O(log n).

## Сложность

**Время — O(log n).** Не зависит от того, насколько «удачно» расположено значение: всегда логарифм.

**Память — O(1).** Рекурсивная реализация потратила бы O(log n) на стек вызовов — ещё один аргумент в пользу итеративной.

## Ловушки

- **`left + right` переполнение.** В языках с фиксированной разрядностью `(left + right) / 2` может переполниться при больших значениях. Безопасная форма — `left + (right - left) / 2`. В JS чисел с переполнением нет, но привычка полезная: так код переносится без сюрпризов.
- **Условие `left <= right`.** Равно обязательно: `left === right` означает отрезок из одного элемента, который ещё нужно проверить. С строгим `<` последний элемент будет пропущен.
- **`mid + 1` / `mid - 1`, а не `mid`.** Если присвоить `left = mid`, на отрезке из двух элементов `mid` всегда равен `left`, и цикл зациклится.

## JS-специфика

На маленьком массиве (до ~20 элементов) линейный поиск через `indexOf` быстрее бинарного: он не тратит время на деление и попадает в кэш процессора. Бинарный поиск начинает выигрывать на сотнях элементов. Не оптимизируй преждевременно — `includes`/`indexOf` почти всегда достаточно.

`Array.prototype.indexOf` в V8 использует линейный поиск даже на отсортированных массивах. Если нужен именно бинарный — его надо писать руками (или взять готовый, но в учебных целях пишем сами).

## Задача

Отсортировать массив — но так, чтобы это было быстро на почти отсортированных данных.

## Инсайт: отсортированный префикс

Так люди сортируют карты в руке. Держим левую часть массива отсортированной, на каждом шаге берём очередной элемент и **вставляем** его в нужное место префикса, сдвигая всё большее вправо.

```js
for (let i = 1; i < n; i += 1) {
  const current = nums[i];
  let j = i - 1;
  while (j >= 0 && nums[j] > current) {
    nums[j + 1] = nums[j];   // сдвиг вправо, освобождая место
    j -= 1;
  }
  nums[j + 1] = current;     // вставляем
}
```

## Почему O(n²) иногда быстрее O(n log n)

Big-O описывает **худший случай** и ничего не говорит про константу. А константа у вставок крошечная: нет рекурсии, нет буфера, нет вызовов функций на каждый элемент — только сравнения и сдвиги в непрерывном куске памяти (что идеально для кэша процессора).

На **почти отсортированном** массиве внутренний `while` почти не выполняется. Каждый элемент сдвигается на 0–1 позицию, и фактическая работа — это O(n), а не O(n²). На таких данных вставки обыгрывают merge sort и quicksort в разы.

Именно поэтому **TimSort** — алгоритм встроенной сортировки V8 — находит в массиве уже отсортированные «прогоны» и досортировывает короткие вставками, вместо того чтобы резать всё рекурсией. Он объединяет сильные стороны обоих.

<Note title="Где Big-O обманывает">
  Две операции одного класса O(n log n) могут отличаться по скорости в 3–5 раз из-за константы:
  объёма выделяемой памяти, числа вызовов функций, паттерна доступа к памяти. Big-O отвечает на
  «как растёт», а не «насколько быстро». Поэтому замерять всегда полезнее, чем гадать.
</Note>

## Сложность

**Время:**
- Худший случай — O(n²), обратный порядок.
- Лучший случай — O(n), уже отсортирован.
- Средний — O(n²).

**Память — O(1).** Сортировка на месте.

**Стабильность — да.** Строгое `>` в `while`: равные элементы не сдвигаются, порядок сохраняется.

## Ловушки

- **Сдвиг, а не обмен.** Правильно — сдвинуть `nums[j + 1] = nums[j]` и поставить `current` один раз в конце. Обмен на каждом шаге (`swap(nums, j, j+1)`) работает, но делает втрое больше записей.
- **`j >= 0` раньше сравнения.** В `while (j >= 0 && nums[j] > current)` порядок критичен: если поменять местами, при `j = -1` обращение `nums[-1]` даст `undefined`, и сравнение с числом даст `false` — но только случайно; на объектах падает.
- **Строгое `>`.** `>=` ломает стабильность: равные элементы начинают меняться местами.

## Когда выбирать вставки

- Малый массив (n < ~20) — константа побеждает асимптотику.
- Почти отсортированные данные — логи событий с запоздалыми записями, инкрементальные обновления.
- Внутри гибридных алгоритмов — именно так TimSort обрабатывает короткие куски.

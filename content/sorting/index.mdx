Сортировка — единственная тема, где своя реализация почти никогда не нужна: `Array.prototype.sort` в V8 — это TimSort, O(n log n), стабильный, обкатанный миллиардами запусков. Тему стоит учить не ради того, чтобы сортировать вручную, а ради двух вещей:

1. Понимать, **что именно** делает встроенная сортировка и за что платишь.
2. Освоить приёмы — «разделяй и властвуй», разбиение, стабильность — которые переиспользуются в десятках других алгоритмов.

## Главный факт про `sort` в JS

```js
[10, 9, 1].sort();        // [1, 10, 9]  ← сравнивает как строки!
[10, 9, 1].sort((a, b) => a - b);  // [1, 9, 10]  ← правильно
```

`sort` без компаратора приводит элементы к строке и сортирует лексикографически. Для чисел это **всегда ошибка**. Компаратор `(a, b) => a - b` — это рефлекс, без него числовая сортировка молча ломается.

Ещё: `sort` **мутирует** исходный массив и возвращает ссылку на него. Хочешь новую коллекцию — `[...arr].sort(...)`.

## Что сравниваем

| Алгоритм | Время (среднее) | Худшее | Память | Стабильность |
|---|---|---|---|---|
| Вставками | O(n²) | O(n²) | O(1) | стабильна |
| Слиянием | O(n log n) | O(n log n) | O(n) | стабильна |
| Быстрая | O(n log n) | O(n²) | O(log n) | нестабильна |
| TimSort (встроенная) | O(n log n) | O(n log n) | O(n) | стабильна |

Ключевые отличия:

- **Стабильность** — сохраняет ли исходный порядок равных элементов. Важно, когда сортируешь по одному полю, ноCare о порядке по другому.
- **Гарантия** — merge sort и TimSort не деградируют ни на каком входе. Быстрая — может до O(n²) на неудачном выборе опорного.
- **Память** — merge sort требует O(n) под буфер слияния, быстрая сортирует на месте.

## Зачем тогда insertion sort

O(n²) звучит безнадёжно. Но на **почти отсортированных** данных внутренний цикл почти не выполняется, и фактическая сложность становится O(n) — с крошечной константой и без выделения памяти.

Именно поэтому TimSort досортировывает короткие и почти готовые подмассивы вставками, а не рекурсией. Асимптотика в худшем случае не отражает реальную стоимость — это отдельный урок темы.

## Стабильность на практике

```js
const users = [
  { name: 'Анна', age: 30 },
  { name: 'Борис', age: 25 },
  { name: 'Вера', age: 30 },
];

// Хочу отсортировать по возрасту, не ломая исходный порядок имён.
// Стабильная сортировка: Анна останется раньше Веры (оба age 30).
users.sort((a, b) => a.age - b.age);
```

Нестабильная сортировка может поменять Анну и Веру местами — и вот это уже баг, который трудно поймать: зависит от входа.

## Что в теме

1. **Сортировка слиянием** — «разделяй и властвуй» в чистом виде, гарантия и стабильность.
2. **Быстрая сортировка** — разбиение вокруг опорного, скорость на практике и капкан худшего случая.
3. **Сортировка вставками** — почему O(n²) иногда быстрее, чем O(n log n).

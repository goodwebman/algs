## Задача

Реализовать мин-кучу: вставку элемента и извлечение минимума, обе за O(log n).

## Инсайт: массив вместо дерева

Дерево кучи — **полное**: все уровни заполнены слева направо, дыр нет. Именно поэтому его можно уложить в массив без потерь и без указателей:

```
      1              массив: [1, 3, 2, 7, 5, 8]
    /   \            индексы:  0  1  2  3  4  5
   3     2
  / \   /
 7   5 8
```

`heap[1]` и `heap[2]` — дети `heap[0]`. `heap[3]` и `heap[4]` — дети `heap[1]`. Формула `2i+1`, `2i+2` работает всегда, потому что дырок нет.

Массив ещё и быстрее дерева с указателями: непрерывная память, попадания в кэш.

## Вставка: всплытие

Новый элемент кладётся в **конец массива** — это самый левый свободный лист, полнота дерева сохраняется. Но свойство кучи может нарушиться: новый элемент может быть меньше родителя.

Чиним всплытием: пока элемент меньше родителя — меняем местами.

```js
while (i > 0) {
  const parent = Math.floor((i - 1) / 2);
  if (heap[parent] <= heap[i]) break;   // на месте
  swap(parent, i);
  i = parent;
}
```

Путь до корня — это высота дерева, то есть **log n** шагов.

## Извлечение: погружение

Минимум всегда в корне — `heap[0]`. Но просто удалить корень нельзя: дерево развалится. Приём: на место корня встаёт **последний лист** (полнота сохраняется), а потом он «тонет» до своего места.

```js
let i = 0;
for (;;) {
  let smallest = i;
  if (left < n && heap[left] < heap[smallest]) smallest = left;
  if (right < n && heap[right] < heap[smallest]) smallest = right;
  if (smallest === i) break;
  swap(i, smallest);
  i = smallest;
}
```

Меняться нужно именно с **меньшим** из двух детей — иначе после обмена родитель окажется больше второго ребёнка, и свойство снова нарушится.

Сначала строится куча вставками, потом минимумы извлекаются подряд — и это даёт отсортированный порядок. Так работает heapsort: O(n log n), на месте, но нестабильная.

## Сложность

| Операция | Время |
|---|---|
| peek (минимум) | O(1) |
| insert | O(log n) |
| extractMin | O(log n) |
| построение из массива | O(n) при heapify снизу вверх |

Построение за O(n), а не O(n log n) — контринтуитивный факт: большинство узлов находятся у листьев, и им нужно мало шагов погружения. Сумма сходится к линейной.

## Ловушки

- **`Math.floor((i - 1) / 2)`.** Без `floor` получится дробный индекс, и `heap[1.5]` вернёт `undefined`.
- **Обмен с большим ребёнком.** В мин-куче нужен **меньший** ребёнок, иначе свойство не восстановится.
- **`pop()` при одном элементе.** После `heap.pop()` куча может стать пустой — тогда погружать нечего, проверка обязательна.
- **Куча ≠ отсортированный массив.** `heap[1]` не второй по величине. Единственная гарантия — `heap[0]` минимален.

## Макс-куча из мин-кучи

Отдельная реализация не нужна: храни отрицания (`-value`) или передай компаратор. Второе чище, если куча обобщённая.

## Решай сам

Задача ниже — самое частое практическое применение кучи: найти k наибольших за O(n log k) вместо O(n log n) сортировкой.

Приём инвертирован относительно интуиции: чтобы найти **наибольшие**, держим **мин**-кучу размера k. В её корне лежит наименьший из текущих кандидатов — именно он вылетает, когда приходит кто-то больше.

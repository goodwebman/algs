Куча отвечает на один вопрос: **«кто сейчас минимальный (или максимальный)?»** — за O(1), и позволяет его извлечь за O(log n).

Это меньше, чем даёт сортировка (полный порядок), и именно поэтому дешевле. Не нужен весь порядок — не плати за него.

## Когда куча выигрывает у сортировки

Задача «найти k наибольших из n элементов»:

- **Сортировка:** O(n log n), потом взять первые k.
- **Куча размера k:** O(n log k).

При k = 10 и n = 1 000 000 разница в разы. А главное — куча работает **на потоке**: элементы могут приходить по одному, и не нужно держать в памяти весь массив.

Второе применение — **Дейкстра**: на каждом шаге нужна ближайшая непосещённая вершина. Куча даёт её за O(log V) вместо линейного поиска за O(V).

## Дерево, которого не существует

Куча рисуется как дерево, но физически это **плоский массив**:

```
родитель узла i  →  Math.floor((i - 1) / 2)
дети узла i      →  2i + 1  и  2i + 2
```

## Свойство кучи слабее сортировки

Единственное правило: **родитель не больше любого из детей** (для мин-кучи). Между братьями порядка нет вообще.

Отсюда важное следствие: куча даёт минимум, но **не даёт «второй по величине» за O(1)** — второй может быть любым из двух детей корня. Нужен полный порядок — нужна сортировка.

Слабость свойства и есть источник дешевизны: при вставке чинить нужно один путь до корня (log n шагов), а не весь массив.

## Две операции

**Вставка:** кладём в конец массива, потом «всплываем» — меняем с родителем, пока меньше него. O(log n).

**Извлечение минимума:** корень уходит, на его место встаёт последний лист, потом «тонет» — меняется с меньшим из детей, пока не встанет на место. O(log n).

## В JS кучи нет

Ни в стандартной библиотеке, ни во встроенных структурах. `Array.prototype.sort` + `shift` — это O(n log n) на построение и O(n) на извлечение, то есть не куча.

Приходится писать руками (~40 строк) или брать библиотеку. Для задач с k ≪ n это окупается.

## Задача

Дан массив **положительных** чисел и число `target`. Найти минимальную длину непрерывного подмассива с суммой не меньше `target`. Если такого нет — вернуть 0.

## Инсайт: расширяй, пока мало; сжимай, пока можно

Окно переменного размера работает по шаблону из трёх шагов:

1. `right` расширяет окно — сумма растёт;
2. как только сумма достигла `target`, окно **допустимо** — запоминаем длину;
3. пробуем сжать слева: вдруг условие всё ещё выполняется, а окно короче.

Шаг 3 обязательно `while`, а не `if`. На входе `[1, 1, 1, 10]` с target 10 после того, как окно дошло до десятки, сжимать нужно три раза подряд.

```js
while (sum >= target) {
  minLen = Math.min(minLen, right - left + 1);
  sum -= nums[left];
  left += 1;
}
```

## Почему нужна положительность

Вся схема держится на монотонности: **расширение обязано увеличивать сумму, сжатие — уменьшать**. С отрицательными числами это неверно.

На входе `[10, -20, 100]` с target 100 алгоритм найдёт окно `[100]` и остановится, что здесь случайно правильно. Но на `[100, -1, 1]` с target 100 он схлопнет окно до `[100]`, а `[100, -1, 1]` тоже подходит — и вообще, поведение перестаёт быть предсказуемым.

Для отрицательных нужны префиксные суммы: `sum[j] − sum[i] ≥ target`, и это уже задача другого класса.

## Сложность

**Время — O(n).** Внутренний `while` пугает, но `left` только растёт: за весь алгоритм он сделает максимум `n` шагов. Суммарно каждый указатель проходит массив один раз.

**Память — O(1).**

## Ловушки

- **`Infinity` как начальное значение.** Ответ «не найдено» — это 0, а не `Infinity`. Не забыть преобразовать в конце.
- **Обновление ответа не в том месте.** Длину надо запоминать **до** вычитания `nums[left]`, иначе окно уже другое.
- **`>=` против `>`.** Условие задачи — «не меньше target». `>` даст неверный ответ ровно на тех входах, где сумма попадает в target точно.

## Задача

Run-Length Encoding: `"aaabbc"` → `"a3b2c1"`. Кодируем серии одинаковых символов подряд.

## Инсайт: приём с последней серией

Наивная реализация теряет последнюю серию: цикл заканчивается, а накопленный счётчик так и не записан. Обычно это чинят дублированием кода после цикла.

Красивее — гонять цикл **до `length` включительно**:

```js
for (let i = 1; i <= chars.length; i += 1) {
  if (chars[i] === chars[i - 1]) {
    count += 1;
    continue;
  }
  parts.push(chars[i - 1] + count);
  count = 1;
}
```

На последней итерации `chars[i]` равен `undefined` и не совпадёт ни с чем — ветка «серия закончилась» срабатывает сама, и финальный сброс происходит без отдельного кода после цикла.

Приём работает потому, что обращение за границу массива в JS даёт `undefined`, а не ошибку. В языке с проверкой границ так не напишешь.

## Собирай в массив, а не в строку

```js
// ❌ формально O(n²): строки иммутабельны, каждая конкатенация создаёт новую
result += char + count;

// ✅
parts.push(char + count);
return parts.join('');
```

V8 оптимизирует конкатенацию через «ropes» (ленивое дерево строк), поэтому на практике разница меньше, чем в теории. Но полагаться на оптимизацию движка — плохая привычка, а `join` не медленнее и читается так же.

## Ловушки

- **Многозначные счётчики.** `"a".repeat(12)` → `"a12"`, а не `"a1a2"`. Счётчик просто число, склеивается как есть.
- **Пустая строка.** Ранний выход, иначе `chars[0]` при пустом массиве даст `undefined` в результат.
- **Юникод.** `[...input]` вместо `input[i]` — иначе эмодзи разрежется пополам.
- **Декодирование.** Обратная операция неоднозначна, если в исходной строке были цифры: `"a12"` — это «a двенадцать раз» или «a один раз, 2 один раз»? В реальных форматах символ и число разделяют.

## Сложность

**Время — O(n).** Один проход.

**Память — O(n)** на результат. В худшем случае (все символы разные) результат **длиннее** входа: `"abc"` → `"a1b1c1"`. RLE эффективен только на данных с длинными сериями — растровая графика, факс, простые изображения.

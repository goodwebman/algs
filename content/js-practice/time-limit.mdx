## Задача

`timeLimit(fn, ms)` возвращает обёртку: если `fn` успела за `ms` — результат проходит как есть, если нет — промис **отклоняется**.

## Инсайт: гонка промисов

```js
return Promise.race([fn(...args), timeout]);
```

`Promise.race` завершается тем, что пришло первым. Сработал таймер раньше — получаем отклонение; успела функция — её результат.

## Ловушка, ради которой задача и существует

```js
// ❌ первый аргумент исполнителя — resolve, а не reject
const timeout = new Promise((reject) => {
  setTimeout(() => reject('Time Limit Exceeded'), ms);
});
```

Переменная **названа** `reject`, но фактически это `resolve`. По таймауту промис **успешно резолвится** строкой вместо отклонения.

Коварство в том, что снаружи это почти незаметно: значение приходит, текст правильный. Но `try/catch` не срабатывает, `.catch()` не вызывается, и вызывающий код считает, что всё прошло успешно.

```js
// ✅ reject — ВТОРОЙ аргумент
new Promise((_resolve, reject) => { ... });
```

## Вторая ловушка: незакрытый таймер

```js
clearTimeout(timerPromise);   // ❌ это промис, а не ID таймера
```

`clearTimeout` принимает то, что вернул `setTimeout`. Передать туда промис — значит не отменить ничего.

Без отмены таймер висит, даже если функция уже вернула результат. В Node это держит процесс живым до срабатывания; в браузере — лишняя работа, заметная на тысячах вызовов.

```js
let timer;
const timeout = new Promise((_resolve, reject) => {
  timer = setTimeout(() => reject('Time Limit Exceeded'), ms);
});

try {
  return await Promise.race([fn(...args), timeout]);
} finally {
  clearTimeout(timer);   // ✅ и в успехе, и в ошибке
}
```

`finally`, а не строка после `return` — иначе при отклонении очистка не выполнится.

## Что race не делает

`Promise.race` **не отменяет** проигравший промис. Если `fn` — сетевой запрос, он продолжит выполняться, просто результат никто не увидит. Настоящая отмена — `AbortController`, и его нужно прокидывать в саму `fn`.

Массив в JavaScript — это не массив. Точнее, не обязательно тот массив, о котором говорят в учебниках по алгоритмам: непрерывный кусок памяти с прямой адресацией. Спецификация описывает массив как **объект с целочисленными ключами**, и только оптимизации движка делают его быстрым.

Из этого следуют все практические выводы темы.

## Цена операций

| Операция | Сложность | Что происходит |
|---|---|---|
| `a[i]` | O(1) | прямая адресация — пока массив «плотный» |
| `push` / `pop` | O(1)* | работа с концом, иногда перевыделение буфера |
| `shift` / `unshift` | **O(n)** | все индексы сдвигаются на единицу |
| `splice(i, …)` | **O(n)** | хвост после i переезжает |
| `indexOf` / `includes` | O(n) | линейный перебор |
| `slice` / `concat` / спред | O(n) | копирование |
| `sort` | O(n log n) | TimSort |

Звёздочка у `push` — про амортизацию: обычно O(1), изредка O(n) на перевыделение, в сумме на серию операций всё равно O(1) на элемент.

<Note tone="trap" title="Главная ловушка темы">
  `shift`, `unshift` и `splice` выглядят как одна операция и читаются как одна операция. Но каждая
  из них — это O(n). Внутри цикла они превращают линейный алгоритм в квадратичный, и это самая
  частая скрытая O(n²) в реальном JS-коде.
</Note>

## Форма массива в V8

V8 хранит массивы в нескольких режимах, от быстрого к медленному:

- `PACKED_SMI_ELEMENTS` — только маленькие целые, без дырок. Самый быстрый.
- `PACKED_DOUBLE_ELEMENTS` — числа, включая дробные.
- `PACKED_ELEMENTS` — что угодно, без дырок.
- `HOLEY_*` — то же самое, но с дырками: доступ обязан проверять цепочку прототипов.
- `DICTIONARY_ELEMENTS` — словарь. Доступ по индексу больше не O(1) в привычном смысле.

Переход всегда в одну сторону: массив может испортиться, но не может улучшиться обратно.

Как испортить массив случайно:

```js
const a = [1, 2, 3];
delete a[1];        // дырка → HOLEY
a[100] = 5;         // дырка в 96 ячеек → HOLEY
const b = new Array(10);      // сразу HOLEY
const c = new Array(10).fill(0); // а вот так PACKED
```

Практика: **если знаешь размер — создавай через `new Array(n).fill(значение)`**, а для удаления элемента используй перезапись, а не `delete`.

## Строка — это не массив символов

`"👍".length === 2`. Строки хранятся как последовательность UTF-16 code units. Символы за пределами BMP (эмодзи, редкие иероглифы, некоторые математические знаки) занимают по две ячейки.

```js
const s = '👍ok';
s.length;       // 4
s[0];           // половина эмодзи
[...s];         // ['👍', 'o', 'k'] — спред идёт по code points
```

Правило: индексирование и `split('')` режут по code units, спред и `for…of` — по code points. Для задач с произвольным пользовательским текстом это разница между работающим кодом и мусором.

Ещё: **строки иммутабельны**. Конкатенация в цикле создаёт новую строку на каждой итерации — формально O(n²). V8 оптимизирует это через ropes (ленивую конкатенацию), но полагаться на оптимизацию не стоит: собирай в массив и делай `join('')`.

## Приём темы: два указателя внутри одного массива

Раз удалять и вставлять дорого, а перезаписывать дёшево — все операции «на месте» строятся по одной схеме:

- **fast** читает исходные данные;
- **slow** отмечает границу уже собранного ответа;
- всё, что левее slow, — результат; всё правее — мусор, который никого не волнует.

Функция возвращает не новый массив, а **новую длину**. Это выглядит непривычно после `filter`, но именно так достигается O(1) по памяти.

## Что в теме

1. **Удаление дубликатов на месте** — схема slow/fast в чистом виде.
2. **Перенос нулей в конец** — та же схема, но с обменом ради сохранения порядка.

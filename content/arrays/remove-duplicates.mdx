## Задача

Дан **отсортированный** массив. Удалить повторы так, чтобы каждое значение осталось ровно один раз. Работать на месте, дополнительная память — O(1). Вернуть новую длину.

Первые `k` элементов массива после работы функции должны содержать ответ; что лежит дальше — не важно.

## Почему возвращается длина, а не массив

Это выглядит странно после привычного `[...new Set(nums)]`, но требование O(1) по памяти запрещает создавать новый массив. А удалить элемент из середины существующего нельзя дешевле, чем за O(n) — `splice` сдвинет весь хвост.

Единственный способ уложиться в O(1) — **перезаписывать префикс** и сообщить вызывающему, докуда он валиден.

## Инсайт: два указателя с разной скоростью

- `fast` читает исходные данные и идёт всегда;
- `slow` показывает на последний записанный уникальный элемент.

**Инвариант:** `nums[0..slow]` — это уже готовый ответ, все элементы в нём различны и отсортированы.

Раз массив отсортирован, все копии одного значения лежат рядом. Значит достаточно сравнить текущий элемент с последним записанным: если равны — это дубликат, пропускаем; если нет — новое значение, пишем на следующую позицию.

Сравнение именно с `nums[slow]`, а не с `nums[fast - 1]`: второе тоже сработает на отсортированном массиве, но развалится, если условие задачи чуть изменить (например, «оставить не более двух копий»).

## Сложность

**Время — O(n).** `fast` проходит массив один раз, `slow` двигается не чаще.

**Память — O(1).** Две переменные. Обрати внимание: в разборе есть `[...input]` — это только чтобы не портить входные данные визуализации. В настоящем решении массив мутируется на месте.

## Ловушки

- **Пустой массив.** `slow = 0` при пустом входе — уже неверно: ответ должен быть 0, а не 1. Ранний выход обязателен.
- **Начинать `fast` с нуля.** Первый элемент всегда уникален (сравнивать не с чем), поэтому цикл идёт с `fast = 1`.
- **Массив не отсортирован.** Алгоритм молча вернёт мусор: `[1,2,1]` даст `[1,2,1]` и длину 3.

## JS-специфика: почему не `Set`

```js
const unique = [...new Set(nums)];
```

Одна строка, работает на любом массиве, не требует сортировки. В обычном коде я написал бы именно так.

Но это O(n) памяти и заметно более тяжёлая константа: хеширование каждого элемента против одного сравнения. На отсортированных данных вариант с указателями быстрее в разы и не аллоцирует вообще ничего.

Вывод не «`Set` плохой», а: **когда данные уже упорядочены, это ресурс — его надо тратить, а не игнорировать**.

## Задача

Сдвинуть все нули в конец массива, **сохранив относительный порядок** остальных элементов. На месте, без создания нового массива.

`[0, 1, 0, 3, 12]` → `[1, 3, 12, 0, 0]`.

## Наивные решения и что с ними не так

**Через `filter` и дозаполнение:**

```js
const nonZero = nums.filter((x) => x !== 0);
// ...дописать нули
```

Работает, но это O(n) дополнительной памяти — а условие просит на месте.

**Через `splice` в цикле:**

```js
// ❌ O(n²)
for (let i = 0; i < nums.length; i += 1) {
  if (nums[i] === 0) {
    nums.splice(i, 1);
    nums.push(0);
  }
}
```

Здесь сразу две беды. `splice` сдвигает весь хвост — это O(n) на каждый ноль, итого O(n²). И вдобавок цикл сломан: после `splice` элементы сдвинулись, а `i` увеличился — соседний ноль будет пропущен.

## Инсайт: обмен вместо сдвига

Опять slow и fast, но теперь с обменом:

- `fast` ищет очередное **ненулевое** значение;
- `slow` показывает на первую позицию, куда это значение должно встать.

**Инвариант:** слева от `slow` нулей нет и порядок правильный; между `slow` и `fast` — только нули.

Когда `fast` находит ненулевое, оно меняется местами с `nums[slow]`. Ноль при этом уезжает вправо — ровно туда, где он и должен оказаться.

<Note title="Почему именно обмен сохраняет порядок">
  Между `slow` и `fast` лежат **только нули** — это и есть смысл инварианта. Значит обмен переносит
  ненулевое значение через блок нулей и не может перепрыгнуть через другое ненулевое. Относительный
  порядок ненулевых сохраняется автоматически.
</Note>

## Сложность

**Время — O(n).** Один проход, каждый элемент участвует максимум в одном обмене.

**Память — O(1).** Две переменные-индекса.

Заметь, что обменов делается ровно столько, сколько ненулевых элементов стоит не на своём месте. На массиве без нулей обменов не будет вообще — проверка `slow !== fast` отсекает бессмысленный обмен элемента с самим собой.

## Ловушки

- **`-0`.** `-0 === 0` даёт `true`, так что минус-ноль тоже уедет в конец. Обычно это и нужно, но если нет — сравнивай через `Object.is`.
- **Разреженный массив.** `[0, , 1]` содержит дырку, и `nums[1]` вернёт `undefined`, а не `0`. Алгоритм посчитает дырку «ненулевой» и переставит её как обычное значение.
- **Модификация длины внутри цикла.** Любой `push`/`splice` в теле цикла сделает поведение непредсказуемым — здесь мы только меняем элементы местами, длина неизменна.

## JS-специфика: деструктурирующий обмен

```js
[nums[slow], nums[fast]] = [nums[fast], nums[slow]];
```

Читается отлично, но формально создаёт временный массив на каждой итерации. V8 в большинстве случаев его устраняет (escape analysis), однако в горячем коде классический вариант через временную переменную предсказуемее:

```js
const tmp = nums[slow];
nums[slow] = nums[fast];
nums[fast] = tmp;
```

Разница заметна только на миллионах операций. Пиши деструктуризацию, пока профайлер не сказал обратное.

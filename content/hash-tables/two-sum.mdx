## Задача

Дан **неотсортированный** массив и число `target`. Вернуть индексы двух разных элементов с суммой `target`.

Отличие от [версии с отсортированным массивом](/t/two-pointers/two-sum-sorted) кажется мелким, но оно ломает весь подход: два указателя здесь не работают.

## Почему два указателя не подойдут

Вся схема двух указателей держится на фразе «если сумма краёв мала, левый элемент можно выбросить, потому что все остальные не больше правого». На неотсортированном массиве это неправда — где угодно может лежать огромное число.

Можно отсортировать. Но сортировка стоит O(n log n) **и уничтожает исходные индексы**, а вернуть надо именно их. Пришлось бы тащить пары `[значение, индекс]` — работает, но громоздко.

## Инсайт: не ищи пару, ищи недостающее

Переформулируем. Вместо «найти два элемента с суммой target» — «для каждого элемента проверить, встречалось ли ранее число `target − nums[i]`».

Второй вопрос отвечается за O(1), если хранить уже увиденные числа в `Map`. Один проход, никакой сортировки, индексы на месте.

```js
const need = target - nums[i];
if (seen.has(need)) return [seen.get(need), i];
seen.set(nums[i], i);
```

<Note tone="trap" title="Порядок двух строк критичен">
  Сначала **проверка**, потом **запись**. Наоборот — и элемент найдёт сам себя: на входе `[3]` с
  target 6 вернётся `[0, 0]`, хотя правильный ответ — `null`.
</Note>

## Сложность

**Время — O(n).** Один проход, внутри — константные операции `Map`.

**Память — O(n).** В худшем случае (ответа нет) в `Map` попадут все элементы. Это и есть цена сделки: та же задача на отсортированном массиве решается за O(1) памяти.

## Ловушки

- **Дубликаты значений.** `Map` хранит одно значение на ключ. Если задача требует все пары, а не первую, храни массив индексов: `seen.set(x, [...(seen.get(x) ?? []), i])`.
- **Сравнение ключей в `Map` — это SameValueZero.** Практически это значит две вещи: `0` и `-0` считаются одним ключом (`new Map([[0, 'a']]).get(-0)` вернёт `'a'`), а `NaN` **находится** по ключу `NaN`, хотя `NaN === NaN` даёт `false`. Обычный поиск через `indexOf` так не умеет — там `NaN` не найдётся никогда.
- **Использование `Object` вместо `Map`.** С числовыми ключами объект будет неявно приводить их к строкам, а с отрицательными и дробными числами это ещё и меняет порядок обхода.

## JS-специфика

`Map` в V8 — это хеш-таблица с открытой адресацией и отдельным массивом для порядка вставки. Вставка и чтение амортизированно O(1). При росте таблица перевыделяется (rehash), поэтому если размер известен заранее, дешевле создать `new Map(entries)` сразу, чем добавлять по одному.

`Set` — та же структура без значений. `set.has(x)` быстрее, чем `array.includes(x)`, начиная примерно с десятка элементов; на трёх элементах массив выигрывает за счёт отсутствия хеширования.

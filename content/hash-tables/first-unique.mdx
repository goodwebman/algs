## Задача

Найти индекс первого символа строки, который встречается в ней ровно один раз. Если таких нет — вернуть `−1`.

`"leetcode"` → `0` (буква `l`). `"loveleetcode"` → `2` (буква `v`). `"aabb"` → `−1`.

## Наивное решение

```js
// ❌ O(n²)
for (let i = 0; i < s.length; i += 1) {
  if (s.indexOf(s[i]) === s.lastIndexOf(s[i])) return i;
}
```

Читается неплохо, но каждый `indexOf` — это полный проход по строке. Итого O(n²): на строке в 100 000 символов это 10 миллиардов операций.

## Инсайт: за один проход ответить нельзя

Тут есть важный момент, который многие пытаются обойти. **Уникальность символа на позиции 3 нельзя подтвердить, не досмотрев строку до конца** — он может повториться на позиции 100 000.

Значит нужно два прохода:

1. Посчитать частоту каждого символа.
2. Пройти строку заново и вернуть первый символ с частотой 1.

Два прохода — это `2n` операций, то есть по-прежнему **O(n)**. Константа в Big-O отбрасывается, и это правильно: 2n растёт линейно, а n² — нет.

<Note title="Почему второй проход идёт по строке, а не по Map">
  Порядок вставки в `Map` совпадает с порядком первого появления символа, так что технически можно
  пройти по `Map` и найти первую запись со значением 1. Это даже быстрее — записей меньше, чем
  символов. Но тогда придётся отдельно хранить индекс первого вхождения. По строке — проще и
  очевиднее.
</Note>

## Сложность

**Время — O(n).** Два линейных прохода.

**Память — O(k)**, где k — размер алфавита, а не длины строки. Для латиницы это максимум 26 записей независимо от того, миллион символов в строке или десять.

Это важное различие. Если бы алфавит был ограничен ASCII, можно было бы взять массив на 128 ячеек и получить настоящую O(1) память. Для юникода так не выйдет — символов больше миллиона.

## Ловушки

- **`counts[char]++` на объекте.** Для нового символа `counts[char]` даёт `undefined`, и `undefined + 1` — это `NaN`. Нужен либо `(counts[char] ?? 0) + 1`, либо `Map` с явным дефолтом.
- **Объект вместо `Map` с опасными ключами.** Символ `"constructor"` не бывает, но в задачах про слова — легко. `{}["constructor"]` вернёт функцию, а не `undefined`, и счётчик сломается. `Object.create(null)` или `Map` от этого защищают.
- **Строки и code points.** `"👍a"` — три code units, два символа. Если задача про эмодзи, обходи через `[...s]` или `for…of`, а не по индексам.

## JS-специфика: чем `Map` лучше объекта в этой задаче

Ключи здесь динамические — заранее неизвестно, какие символы придут. Это ровно тот случай, где V8 деоптимизирует объект: каждый новый ключ меняет «форму» (hidden class), и после нескольких десятков изменений объект переходит в словарный режим, где доступ медленнее.

`Map` спроектирован под такой сценарий и стабилен по производительности. Плюс `.size` за O(1) против `Object.keys(o).length` за O(n).

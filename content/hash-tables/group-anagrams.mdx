## Задача

Разложить массив слов по группам так, чтобы в одной группе оказались слова из одинаковых букв.

`["eat","tea","tan","ate","nat","bat"]` → `[["eat","tea","ate"], ["tan","nat"], ["bat"]]`.

## Наивное решение

Сравнить каждое слово с каждым: «являются ли они анаграммами?» Это O(n²) сравнений, каждое по O(k log k) — итого O(n² · k log k). На тысяче слов уже неприятно.

Но главное даже не скорость. Такой подход требует отвечать на вопрос «похожи ли A и B» — а это всегда дороже, чем «к какой группе принадлежит A».

## Инсайт: канонический вид

Придумаем для слова **представление, которое одинаково у всех анаграмм и различно у неанаграмм**. Простейшее — отсортированные буквы:

```
eat → aet
tea → aet
ate → aet
tan → ant
bat → abt
```

Теперь задача — тривиальная группировка по ключу в `Map`. Один проход.

Это не трюк для одной задачи, а общий приём. Числа-перестановки цифр (`123` и `321`) → отсортированные цифры. Точки на одной прямой → нормализованный наклон. Изоморфные строки → шаблон замен. Как только канонический вид найден, задача схлопывается до `Map`.

## Сложность

**Время — O(n · k log k)**, где n — количество слов, k — средняя длина. Сортировка каждого слова доминирует.

Можно и за **O(n · k)**: вместо сортировки построить ключ как счётчик букв, например `"a2b0c0…"`. Быстрее асимптотически, но ключ длиннее (26 позиций даже для слова из двух букв) и читается хуже. На словах естественного языка (k ≈ 5–10) сортировка практически всегда выигрывает: `log 10` — это чуть больше трёх.

Классический случай, когда лучшая асимптотика не значит более быстрый код.

**Память — O(n · k)** на хранение всех слов в группах.

## Ловушки

- **`word.split('').sort().join('')` на юникоде.** `split('')` режет по code units и ломает эмодзи. Для слов из букв — безопасно, для произвольных строк — `[...word]`.
- **Объект вместо `Map`.** Ключ `"constructor"` из слова `"constructor"` даст доступ к прототипу. Здесь это не гипотетика: слова приходят из данных.
- **Сортировка мутирует.** `[...word].sort()` работает с новым массивом, но если ты сортируешь массив, полученный откуда-то ещё, — испортишь его.

## JS-специфика

`Array.prototype.sort` без компаратора сравнивает элементы **как строки**. Для букв это ровно то, что нужно, — лексикографический порядок. Для цифр — ловушка: `[10, 9, 1].sort()` даёт `[1, 10, 9]`.

С версии ES2019 сортировка обязана быть **стабильной**, и в V8 это TimSort. Стабильность здесь не важна (мы сортируем символы), но пригодится в задачах, где нужно сохранить исходный порядок равных элементов.

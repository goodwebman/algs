## Задача

Проверить, является ли бинарное дерево деревом поиска: **всё** левое поддерево меньше узла, **всё** правое больше.

## Неправильное решение, которое пишут почти все

```js
// ❌ НЕВЕРНО
const isBst = (node) =>
  !node ||
  ((!node.left || node.left.value < node.value) &&
   (!node.right || node.right.value > node.value) &&
   isBst(node.left) && isBst(node.right));
```

Проверка **локальна**: сравнивает узел только с непосредственными детьми. А свойство BST **глобально**.

Контрпример:

```
      5
    /   \
   1     6
        / \
       3   7
```

Здесь `3 < 6` (левый ребёнок меньше родителя ✓) и `6 > 5` (правый ребёнок больше корня ✓). Локальная проверка проходит. Но `3` лежит в **правом поддереве корня 5** и обязана быть больше 5. Это не BST.

## Правильно: in-order обход со стеком

Опирается ровно на то свойство из [обходов](/t/trees/tree-traversals): in-order (левое → узел → правое) на BST выдаёт значения **строго по возрастанию**. Значит достаточно сравнивать каждый узел с предыдущим:

```js
const stack = [];
let prev = -Infinity;
let current = root;

while (stack.length || current) {
  while (current) {          // спуск влево до упора
    stack.push(current);
    current = current.left;
  }

  current = stack.pop();
  if (current.value <= prev) return false;
  prev = current.value;

  current = current.right;   // и то же самое для правого поддерева
}
```

Обход итеративный: рекурсия на вырожденном дереве (миллион узлов в цепочку) переполнит стек вызовов, а явный стек живёт в куче. Выход при первом же нарушении — ранний, дообходить дерево не нужно.

## Сложность

**Время — O(n).** Каждый узел кладётся на стек и снимается ровно один раз.

**Память — O(h)** на явный стек, где h — высота дерева.

## Ловушки

- **Нестрогие неравенства.** В классическом BST дубликаты не допускаются: `<=` и `>=`. Если условие задачи разрешает дубликаты слева — сравнение слева станет `<`, а справа останется `>=`. Это решение задачи, а не деталь реализации.
- **`Infinity` как границы.** Работает, пока значения — обычные числа. Если в дереве могут быть `Infinity`, нужны `null`-границы с явной проверкой.
- **Забыть про `prev` между поддеревьями.** Предыдущее значение — общее состояние всего обхода, а не локальная переменная ветки. Если завести его внутри рекурсии, проверка развалится ровно на «хитром» дереве.

## Альтернатива: передавать диапазон вниз

```js
const check = (node, min, max) => {
  if (!node) return true;
  if (node.value <= min || node.value >= max) return false;

  return check(node.left, min, node.value)    // влево: сужаем верх
      && check(node.right, node.value, max);  // вправо: сужаем низ
};

check(root, -Infinity, Infinity);
```

Уходя влево, узел становится **верхней** границей для всего поддерева. Уходя вправо — **нижней**. Так глобальное свойство проверяется локально, но с накопленным контекстом. Ответ тот же; выбор между подходами — вопрос вкуса, пока дерево не настолько глубокое, чтобы рекурсия стала проблемой.

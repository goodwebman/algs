## Задача

Обойти бинарное дерево и собрать значения узлов тремя способами: pre-order, in-order, post-order.

## Инсайт: меняется одна строка

Порядок посещения **детей** всегда одинаков — сначала левый, потом правый. Меняется только позиция строки «обработать узел»:

```js
function walk(node) {
  if (!node) return;

  // визит(node);   ← pre-order
  walk(node.left);
  // визит(node);   ← in-order
  walk(node.right);
  // визит(node);   ← post-order
}
```

Три разных алгоритма — три позиции одной строки. Это не мнемоника, а буквально устройство обхода.

## Зачем какой обход

**Pre-order** — узел обработан **до** детей. Значит на момент обработки мы знаем путь от корня и ничего не знаем о поддереве. Подходит для сериализации (записать структуру сверху вниз), копирования дерева, вывода вложенных списков.

**In-order** — на BST даёт **отсортированный порядок**. Это следствие определения: всё левое поддерево меньше узла, всё правое больше. Отсюда «k-й наименьший элемент BST» решается за O(k) без сортировки.

**Post-order** — узел обработан **после** детей. Значит на момент обработки уже известны результаты поддеревьев. Подходит для вычислений снизу вверх: размер поддерева, высота, сумма, удаление (нельзя удалить узел до детей — потеряем ссылки).

## Сложность

**Время — O(n).** Каждый узел посещается ровно один раз.

**Память — O(h)** на стек вызовов, где h — высота. Сбалансированное дерево — O(log n), вырожденное — O(n).

## Ловушки

- **Забыть базовый случай.** `if (!node) return` обязателен: без него обращение к `null.left` упадёт.
- **Перепутать in- и pre-order.** На симметричных примерах разница незаметна. Проверяй на дереве, где корень не в середине.
- **Итеративный in-order сложнее.** Pre-order через стек тривиален; in-order требует спуска до самого левого узла с накоплением стека. Post-order итеративно — самый неприятный из трёх (два стека или отслеживание последнего посещённого).

## Итеративный вариант

```js
// pre-order без рекурсии
const stack = [root];
while (stack.length) {
  const node = stack.pop();
  if (!node) continue;
  result.push(node.value);
  stack.push(node.right);  // правый раньше — чтобы левый обработался первым
  stack.push(node.left);
}
```

Порядок `push` обратный порядку обхода: стек LIFO, поэтому последний положенный достанется первым.

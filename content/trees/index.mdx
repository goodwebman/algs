Дерево — иерархия: у каждого узла один родитель и сколько угодно детей, циклов нет. DOM, файловая система, JSON, дерево компонентов React, план выполнения SQL-запроса — всё это деревья.

## Словарь

- **Корень** — единственный узел без родителя.
- **Лист** — узел без детей.
- **Высота** — длина самого длинного пути от корня до листа.
- **Бинарное дерево** — не больше двух детей у узла.
- **BST (дерево поиска)** — бинарное, где всё левое поддерево меньше узла, а всё правое больше.

## Высота решает всё

Почти все операции на дереве стоят **O(h)**, где h — высота. И вот тут разница между теорией и практикой:

- **Сбалансированное** дерево: h = log₂(n). Для миллиона узлов — 20.
- **Вырожденное** (каждый узел имеет одного ребёнка): h = n. Дерево превратилось в связный список.

BST, в который вставляют уже отсортированные данные, вырождается **гарантированно**: каждый следующий элемент больше всех предыдущих и уходит вправо. Поиск деградирует с O(log n) до O(n).

Отсюда самобалансирующиеся деревья (AVL, красно-чёрное) — они перестраиваются при вставке, удерживая h = O(log n). В прикладном JS они почти не нужны: есть `Map` с O(1).

## Три обхода в глубину

Разница между ними — **одна строка**: когда обрабатывается сам узел.

| Обход | Порядок | Зачем |
|---|---|---|
| pre-order | узел → левое → правое | копирование дерева, сериализация |
| in-order | левое → узел → правое | **на BST даёт отсортированный порядок** |
| post-order | левое → правое → узел | удаление, подсчёт размеров поддеревьев |

In-order на BST — самое полезное свойство темы: обход даёт значения по возрастанию бесплатно, без сортировки.

## DFS против BFS

- **DFS (в глубину)** — рекурсия или стек. Память O(h). Обходы выше — это DFS.
- **BFS (в ширину)** — очередь. Память O(ширины), в худшем случае O(n) — последний уровень дерева содержит около половины узлов.

Выбор: «нужен кратчайший путь / обход по уровням» → BFS. «Нужно пройти всё / посчитать что-то снизу вверх» → DFS.

<Note tone="trap" title="Глубина рекурсии">
  DFS рекурсией на вырожденном дереве из 100 000 узлов даст `RangeError: Maximum call stack size
  exceeded`. Для деревьев неизвестной формы (например, из пользовательских данных) безопаснее
  итеративный DFS с явным стеком.
</Note>

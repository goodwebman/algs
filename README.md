# Алгоритмы на JavaScript — интерактивный учебник

Каждый алгоритм можно проиграть по шагам, увидеть счётчики сравнений и обменов в реальном времени, сравнить теоретическую кривую сложности с реально замеренным временем и тут же написать своё решение — оно прогонится по тестам прямо в браузере.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

Прочее:

```bash
npm run build      # прод-сборка в dist/
npm run preview    # посмотреть прод-сборку локально
npm run check      # typecheck + lint + тесты
```

## Что внутри

**17 тем**, от оценки сложности до динамического программирования, плюс отдельный трек задач на сам JavaScript. Каждая тема — объяснение приёма, разборы алгоритмов с пошаговой визуализацией и задачи с автотестами.

**Пошаговый плеер.** Указатели, окно, стек, дерево вызовов, граф и DP-таблица рисуются на каждом шаге. Управление с клавиатуры: `Space` — пуск/пауза, `←`/`→` — шаг, `R` — сброс.

**Листинг синхронизирован с визуализацией.** Подсвечивается строка, которая выполняется прямо сейчас.

**Песочница с тестами.** Код исполняется в Web Worker с жёстким таймаутом — бесконечный цикл не вешает вкладку. Есть режим замера роста: решение прогоняется на входах разного размера, и результат ложится поверх теоретических кривых. Наглядно видно, что `unshift` в цикле — это парабола, а не прямая.

## Ключевое архитектурное решение

Каждый алгоритм написан **один раз, как генератор**:

```ts
export function* traceTwoSumSorted(nums, target) {
  // ...
  yield { state: {...}, at: 'sum', note: 'Сумма краёв...' };
}

/** Та же логика без шагов — для тестов. */
export const twoSumSorted = (nums, target) => runTrace(traceTwoSumSorted(nums, target));
```

Визуализация, листинг в статье и юнит-тесты гоняют **физически один и тот же код**. Разойтись им негде.

Листинг берётся из самого файла через `?raw`, а подсвечиваемая строка задаётся якорем в комментарии (`// @sum`), а не номером — номера разъезжаются при первой правке.

## Структура

```
content/           # .mdx — читаются и на GitHub, и в приложении
src/
  algorithms/      # <slug>.algo.ts — генератор + чистая функция + тесты
  tasks/           # <slug>.task.ts — условие, стартовый код, тесты, эталон
  core/            # трассировка, плеер, разбор исходника
  viz/             # 9 рендереров состояний + плеер + графики
  sandbox/         # воркер, тест-раннер, редактор, бенчмарк
  ui/              # вендоренный ui-kit (см. ниже)
  pages/ layout/ store/
```

Алгоритмы и задачи подхватываются по соглашению об именах (`*.algo.ts`, `*.task.ts`) — добавил файл, он появился в учебнике. Ручных списков нет.

## Тесты

```bash
npm test
```

Помимо тестов на каждый алгоритм, есть структурные проверки по всему учебнику разом:

- трассировка каждого пресета завершается, все якоря существуют, у каждого шага есть пояснение;
- эталонное решение каждой задачи проходит её собственные тесты;
- у каждого алгоритма есть страница разбора, каждая задача куда-то вставлена, внутренние ссылки не битые.

Отдельно закрыты регрессиями **8 багов** из первой версии этого репозитория — в том числе потерянная `+1` в скользящем окне, перепутанные `resolve`/`reject` в таймауте промиса и `filter` без колбэка в `EventEmitter`.

## UI-kit

Компоненты вендорены из [UI-KIT-goodwebman](https://github.com/goodwebman/UI-KIT-goodwebman) в `src/ui/` — взято 18 из 43, только реально нужные. Пакет не опубликован в npm, поэтому подключить его зависимостью нельзя.

Обновления из апстрима **не прилетают автоматически** — синхронизировать надо руками. Это осознанная плата за возможность перекрасить компоненты под тему Aurora и не тащить весь кит.

Тема: Aurora Boreal Nórdica, только тёмная. Структура токенов кита сохранена, поменялись значения — все проверены на контраст (текст ≥ 4.5:1, границы и цвета визуализаций ≥ 3:1). Палитра графиков считалась отдельно и проверена на разделимость при дальтонизме.
